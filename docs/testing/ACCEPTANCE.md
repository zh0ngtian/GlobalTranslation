### 私有批量回归入口

`PhotoBatchTest` 默认缺少输入时跳过。将原图和 `manifest.json` 通过 `adb shell run-as` 注入 App 私有 `no_backup/acceptance-batch/`。清单是数组，每项包含 `id`、`file`、`script`（`LATIN` 或其他已支持体系）、可选 `rotation`（本次侧转图为 `270`）。

- `phase=ocr`：只运行真实本地 OCR。
- `phase=api`：通过 stdin 注入 `no_backup/acceptance-api-key` 后运行；测试读取后立即删除临时 Key，调用现有生产翻译器。
- `phase=replay`：每个输入旁放置此前的 `<id>-result.json`，验证 OCR ID 与原文一致后回放译文，不调用 API。

入口：`adb shell am instrument -w -e phase replay -e class com.example.globaltranslation.PhotoBatchTest com.example.globaltranslation.test/androidx.test.runner.AndroidJUnitRunner`。导出 `cache/photo-batch/` 中的 JSON、PNG、`failures.json` 后清理手机上的注入文件与缓存。测试源码只包含通用入口，不包含私有照片内容或 Key。

## 2.4：密集分栏 OCR 与原图切换（2026-09-29）

正向页面新增词坐标分栏、密集小字的栏间空白检测、栏内重叠切块识别、位置去重及阅读顺序重建。栏边在不同高度可随透视移动，分组时沿用相应高度的栏界，避免再次按固定竖线混入邻栏碎片。原图及切块仍只在本地处理，文字体系仍由用户手选；明显侧转、竖排沿用已有方向处理，可手动旋正后重新识别。

相册显示预览仍限制为 4096 像素，密集识别可以从原始 URI 用 `BitmapRegionDecoder` 按需读取更高分辨率区域。区域处理 EXIF 旋转、镜像及手动旋转后映射回预览坐标。单块读取、释放，不常驻整张原始大图；不支持区域解码的格式回退预览。根据 Android 官方文档，`ImageDecoder.setCrop` 裁切的是输出，不能替代真正的区域解码，故这里使用 [BitmapRegionDecoder](https://developer.android.com/reference/android/graphics/BitmapRegionDecoder)。插值放大不能恢复丢失的笔画；ML Kit 对文字像素尺寸的建议见[输入图像指南](https://developers.google.com/ml-kit/vision/text-recognition/v2/android#input-image-guidelines)。

结果页顶部新增“查看原图／查看译文”。隐藏和恢复所有覆盖底色、译文与失败框，保留缩放、拖动位置，不调用 OCR 或 API。原图模式不触发译文详情。连续替换照片时，原生绘制显式裁剪到自身视口，防止图片遮住顶部按钮。

内置 Prompt 版本升为 `photo-translation-v4`：可读片段正常翻译，不可读片段要求以目标语言标记；模型新增原文没有的省略号时拒绝该批并提示，保留此前成功批次。此规则不能保证模型发现所有乱码。计数改为“已返回”，避免将 ID 齐全表达为识别正确。
